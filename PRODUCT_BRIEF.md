# Product Governance

`PRODUCT_BRIEF.md` previously combined product definition, scope, non-goals, and operating principles in one document. Those concerns are now deliberately separated so they can change at the right rates.

The governing hierarchy is:

> **[Constitution](CONSTITUTION.md) → [Product Vision](PRODUCT_VISION.md) → [Product Strategy](PRODUCT_STRATEGY.md) → [Roadmap](ROADMAP.md) → Issues and PRs**

- **`CONSTITUTION.md`** — what Work Ledger is loyal to: enduring principles, boundaries, evidence standards, human agency, and the Show → Tell → Do discipline. Changes rarely.
- **`PRODUCT_VISION.md`** — the future the product is trying to create and the expanding circles from individual work to shared organizational learning. Changes when the destination changes.
- **`PRODUCT_STRATEGY.md`** — how we test progress toward the vision: evidence levels, measures, strategic bets, and explicit unknowns. Changes when field evidence changes what we believe.
- **`ROADMAP.md`** — the current manifestation of intent: what we are choosing to build or investigate now. Changes as priorities and maturity change.
- **Issues and PRs** — implementation of roadmap intent. They should not silently redefine higher-order artifacts.

This file remains as a compatibility pointer because older documentation and links may still refer to `PRODUCT_BRIEF.md`. New product decisions should cite the governing artifact directly.
